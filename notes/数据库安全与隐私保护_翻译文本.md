2.1 Identity Authentication and Access Control [3] In the security and information system management of databases, access control and identity authentication are two core technologies and strategies that jointly ensure the security of sensitive data and resources. They not only prevent unauthorized access but also ensure that users comply with the prescribed permissions and responsibilities when accessing the system. In the field of network security, identity authentication and access control are key technologies for protecting systems from unauthorized access and potential threats. Identity authentication is the process of verifying a user's identity to ensure that only legitimate users can access system resources; while access control further restricts the access rights of legitimate users to system resources, ensuring the security and integrity of resources. 
2.1.1 Identity Authentication Identity authentication refers to the process of verifying a user's identity through certain technical means to ensure that the user accessing the system is legitimate. Identity authentication technologies can be broadly classified into biometric authentication technology and non-biometric authentication technology. Biometric authentication technology is based on user's biological characteristics such as fingerprints, irises, and voice; whereas non-biometric authentication technology relies on information known to the user (e.g., passwords) or possessions owned by the user (e.g., smart cards, tokens, etc.). The following are three well-known identity authentication methods: 

1. Information Secret-based Identity Authentication: This is the most commonly used identity authentication method, which confirms the user's identity by verifying the password or PIN known to the user. To enhance security, technologies such as dynamic passwords, one-time passwords (OTP), etc., can be employed. 

2. Hardware Token-based Identity Authentication: This method relies on verifying the physical items possessed by the user to confirm their identity, such as smart cards, USB keys, etc. These items typically store keys or certificates related to the user's identity for authentication purposes. 

3. Biometric-based Identity Authentication: This method utilizes the user's biological features for identity verification, such as fingerprint recognition, iris recognition, voice recognition, etc. This method offers high security and accuracy but comes with higher implementation costs. 
2.1.2 Access Control Access control refers to setting rules in the system to restrict which users can access which resources, as well as the manner and permissions of access. The goal of access control is to ensure that only authorized users can access specific resources and to prevent unauthorized operations.

By setting access policies to ensure that legitimate users access system resources within the authorized scope, access control consists of three elements: subjects (users or processes), objects (system resources), and control policies (access rules). Access control can be divided into discretionary access control (DAC) and mandatory access control (MAC). Discretionary access control refers to users having the right to access objects they have created (such as files, data tables) and being able to grant access rights to other users or revoke access rights from users with granted permissions. Mandatory access control refers to the system (managed by specialized system security personnel) uniformly controlling objects created by users, determining which users can perform what type of operations on which objects according to specified rules. Even the creator of an object may not have access to that object after it is created. Object-based access control model (OBAC Model): the main task of DAC or MAC models is one-dimensional permission management of access subjects and controlled objects in the system. When there are many users and a huge amount of information data to handle, the task of managing user permissions becomes extremely cumbersome and difficult to maintain, thereby reducing the security and reliability of the system. Task-based access control model (TBAC Model): it addresses security issues from the perspective of applications and enterprises, establishing security models and implementing security mechanisms from a task-oriented viewpoint, providing dynamic real-time security management in the task processing process. In TBAC, object access permissions control is not static but changes with the context of task execution. TBAC primarily considers the issue of data protection in a workflow environment: in the workflow environment, data processing is related to the previous processing, and corresponding access control follows suit. Therefore, TBAC is a context-sensitive access control model. Additionally, TBAC can implement different access control strategies for different workflows and different task instances within the same workflow. In this sense, TBAC is task-based, indicating that it is an instance-based access control model. Role-based access control model (RBAC Model): the fundamental idea of the RBAC model is to assign access permissions to certain roles, and users obtain access permissions possessed by the roles they play. This is because in many practical applications, users are not the owners of the information resources they can access (these information resources belong to the enterprise or company). Consequently, access control should be based on employee positions rather than on which group an employee is in or who owns the information, meaning access control is determined by the roles each user plays in the department. For instance, a school may have roles such as faculty, teachers, students, and other administrative staff.

为了提高系统的安全性，身份认证和访问控制通常需要结合使用，确保只有合法身份的用户才能执行他们有权进行的操作。身份验证与授权分离：身份认证主要确认用户的身份，而访问控制决定他们可以做什么。在一个健全的系统中，首先验证用户身份，再根据其权限授予访问权限。访问控制策略：在身份认证后，系统需要基于一定的访问控制策略(如 RBAC 或 ABAC)来决定用户对资源的访问级别。例如，管理员拥有全部权限，而普通用户仅能访问基本信息。动态授权：结合身份认证的结果，系统可以根据用户的行为动态调整访问权限，例如，基于上下文信息(如位置、设备、时间等)调整用户权限，增强安全性。

Front-end proxy encryption technology is developed based on application system encryption technology, and its typical form is database encryption products introduced by professional data security vendors. Similar to application system encryption technology, front-end proxy encryption technology encrypts sensitive data before storing it in the database, and stores the ciphertext in the database; however, unlike the former, front-end proxy encryption technology is usually implemented in the form of an independent component product such as "front-end proxy encryption gateway". To avoid serious performance loss in data access and processing caused by data encryption, some database vendors provide extension interfaces and mechanisms at the database engine level. Through these extension interfaces and mechanisms, users of database systems can achieve data encryption and decryption processing through external interface calls, while also reducing the impact on the performance of the database system to a certain extent. Back-end proxy encryption technology is an encryption technology based on the capabilities of the database itself, which can make full use of the database's custom extension capabilities to achieve goals such as storage encryption of data, retrieval of encrypted data, and application transparency. A typical representative capable of perfectly implementing back-end proxy encryption is the Oracle database, which achieves data encryption through "views + triggers + extended indexes + external method calls", while ensuring full application transparency. The value of back-end proxy encryption technology is mainly reflected in two major capabilities: "application transparency and independent access control".

Therefore, in scenarios where there is no desire to modify the application system during encryption or there is a need to control access permissions for superusers of the database, if the encrypted columns involved in the query are not many and the data records in the query result set are relatively few, consider using post-proxy encryption technology to encrypt the database.

Transparent Data Encryption (TDE) relies too much on the database's own extension mechanisms, and the data in the shared memory of the database is also ciphertext, leading to poor performance in some scenarios. Therefore, based on post-proxy encryption technology, Transparent Data Encryption technology has been developed to maintain the advantages of post-proxy encryption while reducing the dependence on the database's extension mechanisms, thereby keeping the performance of the database system at a relatively reasonable level. Transparent Data Encryption, abbreviated as TDE, is a database-side storage encryption technology that is completely transparent to the application system, usually implemented by the database vendor in the database engine - adding a data processing process in the storage management layer of the database engine to encrypt data when it is written from the database shared memory to the data file; and decrypt data when read from the data file to the database shared memory. In other words, the data exists in plaintext form in the database shared memory, while it exists in ciphertext form in the data file. At the same time, due to the transparency of this technology, any legitimate and authorized database user can access and process the data in the encrypted table. Transparent Data Encryption technology, due to its own advantageous characteristics, is suitable for almost all application scenarios with database encryption requirements, especially in scenarios where transparent data encryption is required, or where control of data access permissions for superusers of the database is needed, and in scenarios where high performance is required after encrypting the database.

In database encryption technology, in addition to implementing database encryption from the perspectives of front-end applications and the database itself, database encryption can also be achieved based on the file system or storage hardware that the database relies on. File system encryption technology encrypts files at the level of the operating system's file management subsystem, mostly implemented by modifying the operating system kernel drivers related to the file management subsystem. Unlike file encryption, which sets access passwords for individual files or encrypts the content of individual files, file system encryption provides an encrypted file system format (similar to file system formats such as ext4, xfs, etc.), by setting the disk storage volume or directories on it to the file encryption system format, to achieve the purpose of encrypting files stored in the volume or directories on the volume. File system encryption technology is not fundamentally a database encryption technology but can be used for encrypting data files at the storage layer of the database. File system encryption technology can be applied to almost any database storage encryption requirement based on file systems, especially for database systems and big data database systems that do not natively support transparent data encryption. However, since file system encryption technology cannot provide enhanced access control for database users, it is not suitable for scenarios that require protection against internal database superusers.

2.2.7 Homomorphic Encryption Homomorphic Encryption (HE) is a special encryption technology that allows calculations to be performed on encrypted data without the need to decrypt it first. In other words, data encrypted using homomorphic encryption can undergo mathematical operations (such as addition, multiplication, etc.) without revealing the original data, and the final results, once decrypted, are equivalent to the results of applying the same operations to the original data.

Homomorphic encryption has significant applications, especially in scenarios where privacy of data processing is essential, such as in cloud computing, big data analysis, privacy-preserving computation, etc. It provides a new solution for computing on data without revealing it to the processing party, enabling complex data analysis and processing while ensuring data privacy.

The key feature of homomorphic encryption is that it allows direct operations on encrypted data. Traditional encryption algorithms, such as symmetric and asymmetric encryption, require data to be decrypted before computation can take place, whereas homomorphic encryption allows calculations to be performed on encrypted data while maintaining privacy. Specifically, for an encrypted data E(x), homomorphic encryption allows the following operations to be carried out directly on the encrypted data:
- Addition operation on encrypted data: E(x) + E(y) = E(x + y)
- Multiplication operation on encrypted data: E(x) * E(y) = E(x * y)

These calculations are performed directly on the encrypted data, and the results after decryption are correct, i.e., Dec(E(x) + E(y)) = x + y, and Dec(E(x) * E(y)) = x * y. Therefore, homomorphic encryption allows users to perform calculations on encrypted data, ensuring only the final result is exposed, while the intermediate data remains encrypted. Homomorphic encryption technology provides a revolutionary solution for data privacy protection, allowing users to conduct complex computations and analyses while ensuring data encryption and privacy.

Although homomorphic encryption currently faces challenges in computational efficiency and implementation complexity, with the continuous development of technology, its application prospects in privacy-preserving computation, cloud computing, big data analysis, and other fields are very promising.

Differential privacy [7], as presented in section 2.3, ensures that the participation of any single user does not significantly affect the analysis results, thus protecting personal privacy. The core idea of differential privacy is to add random noise when performing statistical analysis or publishing data, making it difficult for attackers to infer information about individual users from the results. This technology is particularly suitable for handling sensitive data, especially in cases where a balance between privacy protection and data utilization is needed in statistical and data analysis. The advantage of differential privacy is that it provides strong privacy protection while ensuring the effectiveness of data analysis.

The rise of distributed databases [11]: With the advent of the big data era, traditional single-node databases have gradually exposed bottlenecks in scalability, high availability, and performance. Distributed databases emerged and achieved horizontal scalability and high availability by storing data across multiple nodes. In the past three years, distributed database technologies have made significant progress and have become one of the core technologies for big data processing. The advantages of distributed databases lie in their high scalability, high availability, and high performance.

By adding nodes, it is easy to expand storage and computing capabilities to meet the demands of large-scale data processing. Meanwhile, distributed databases utilize multiple replica storage and automatic fault tolerance mechanisms to ensure high availability and reliability of data. In addition, distributed databases improve data processing performance through optimized query algorithms and parallel processing techniques. Taking a well-known e-commerce company as an example, with a large business scale, it needs to process hundreds of millions of visits and transaction requests every day. To meet this challenge, the e-commerce company adopted distributed database technology, storing data on multiple nodes and achieving high availability and performance through load balancing and sharding techniques. This measure not only enhances the stability and response time of the system but also reduces operational costs.
